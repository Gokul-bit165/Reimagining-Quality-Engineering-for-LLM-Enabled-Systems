# ADR-0007: Build-and-run docker execution for "paste a GitHub URL and we test it"

Date: 2026-10-31. Status: accepted. Supersedes the "Docker mode" limitation in ADR-0004 (stock image, no dependencies, no network).

## Context
Until now the promise only held if the user had already deployed an endpoint. Docker mode ran one top-level function in `python:3.12-slim` with `--network none` and no installed packages, so almost no real RAG app worked, and none that call an LLM. R6 still holds: repo code runs only in a sandbox, never on the host.

## Decision
`execution_mode = "docker"` now means: build the repo into an image, run it as a service on an isolated network, and talk to it through the existing endpoint target.

### Pipeline (`qe/ingest/runplan.py`, `docker_runner.py`, `docker_gateway.py`)
1. **Detect (static, `ast.parse` only, nothing is executed).** Order: repo `Dockerfile` (port from `EXPOSE`, default 8000) > FastAPI app object (`uvicorn mod:var`) > Flask app object (`python -m flask --app`) > a top-level `ask/query/answer/chat/...(question)` function with exactly one required argument (served by a generated stdlib HTTP wrapper) > Node `package.json` with a `start` script. The HTTP path is taken from route decorators / `app.post(...)`, overridable per project (`app_path`, `app_port`).
2. **Stage.** A sanitised copy of the repo goes to `runs/builds/<run>/`: no `.git`, `node_modules`, venvs, symlinks, `.env`/`.env.*` (examples kept), `*.pem|*.key|*.p12|*.pfx|id_rsa*`; 200 MiB cap. The generated `Dockerfile.qe` is written last (a repo file of the same name is overwritten).
3. **Generated Dockerfile.** `FROM python:3.12-slim` or `node:22-slim` (tag, no digest), `COPY . /app`, `pip install -r requirements.txt` (or `pip install .` for pyproject/poetry/uv projects; `uv.lock`/`poetry.lock` are not honoured), extras (`uvicorn`, `fastapi`, `flask`) only if absent from the manifest, `USER 65534:65534`, no `ARG`, no secrets, deterministic text.
4. **Build.** `docker build --network default --memory 2g --memory-swap 2g --cpu-quota 100000 --force-rm`, 600 s timeout (the CLI is killed, which cancels BuildKit), image size cap 2 GiB (image removed and run failed if exceeded), log tail scrubbed and truncated to 6000 chars. Never passed: `--build-arg`, `--secret`, `--ssh`, `--allow`, `--privileged`, host network, socket mounts. No provider key exists in the build environment, so a build step cannot read one.
5. **Run.** Per run: an `--internal` bridge network (no route to the internet or the host LAN), the app container on it only, and a gateway sidecar (below). App flags: `--read-only`, `--tmpfs /tmp:rw,noexec,nosuid,size=64m`, `--cap-drop ALL`, `--security-opt no-new-privileges`, `--user 65534:65534` (overrides the Dockerfile `USER`), `--memory 1g --memory-swap 1g --cpus 1 --pids-limit 256 --ipc none --init --ulimit nofile`, json-file log cap, no `-p`, no `-v`, no devices. Wall-clock TTL 30 min (timer closes the run), kill switch (`kill()` interrupts build/health-wait and tears down), health-wait 90 s (container must stay running and answer an HTTP response).
6. **Reachability.** Docker does not publish ports of containers that sit only on an `--internal` network, so the host never talks to the app directly. The gateway container is attached to `bridge` (loopback publish `127.0.0.1:<random>:8000`) and to the internal network; its stdlib TCP forwarder relays to the app. The platform then calls `http://127.0.0.1:<port><path>` through `SandboxedRepoTarget("endpoint", trusted_local=True)`, so SSRF pinning, `target_config` mapping and response parsing stay in one place. `trusted_local` only skips the "do not target the platform's own ports / `/api/` paths" check for this one loopback port; loopback is still required and link-local/metadata stays blocked.
7. **LLM egress (opt-in).** Per project `egress_allowlist` (DNS names or `*.suffix`, max 20, validated; no IPs, ports, schemes). With a list, the app gets `HTTPS_PROXY=http://qegw:3128` and the gateway acts as an HTTP `CONNECT` proxy: port 443 only, host must match the allowlist, resolved addresses must all be globally routable (blocks rebinding to private/metadata addresses), everything else gets 403 and a logged `DENY host:port (reason)`; every decision is a JSON log line, saved on the project as `runtime.egress_log` when the run ends. The proxy only tunnels TLS, so provider keys (passed to the app as env at run time from the in-memory vault, `-e NAME` so values are never in argv) are never visible to it. Without a list the app gets no proxy variables and the run records `egress: none`. Variable names ending `_PROXY` cannot be set through the vault.
8. **Lifecycle.** `resolver._from_store` returns a lazy `ManagedDockerTarget` (nothing is built while handling the HTTP request). `qe.realeval.jobs.work` calls `prepare_target` before the run (failure becomes the evaluation's error) and `close_target` in `finally`, so containers, network, image and staging dir are removed on success, failure, cancel and exception. `atexit` closes live runs. All resources carry labels `qe-run=1`, `qe-run-owner=<pid>`, `qe-run-expires=<epoch>`; the server lifespan runs `reap_orphans()` at start and removes anything whose owner process is dead or whose TTL elapsed (a live process's runs are never touched).
9. **State.** `Project.runtime` (`state` idle/building/starting/ready/failed/stopped, `detail`, `kind`, `egress`, `build_log`, `run_log`, `egress_log`) is persisted on every transition and appears in `GET /api/projects/{id}`. `analysis.mode_reason` / `run_kind` explain the chosen mode.
10. **Mode selection.** `choose_mode_detailed`: endpoint if an endpoint URL is set; otherwise `docker` only if the daemon answers AND detection finds a way to run the repo; otherwise `static_only` with a precise reason (`no entrypoint detected ...`, `docker daemon not running`, `docker is not installed`). A build failure is reported at run time (`build failed: ...`) because building is too expensive to do at ingest.

## Threat model additions
| Threat | Mitigation | Residual |
|---|---|---|
| Hostile build steps (`RUN` in a repo Dockerfile, `setup.py`, npm scripts) | Run inside the build container only, memory/CPU/time/size capped, no secrets or build args, nothing mounted from the host | The build container has default-bridge network (needed for pip/npm), so it can reach the internet and, on some Docker setups, the LAN / `host.docker.internal`. Not isolated like the run phase. Hostile `--index-url` in `requirements.txt` is honoured. |
| Hostile app at run time | Internal network, read-only rootfs, cap-drop ALL, no-new-privileges, non-root, limits, TTL, label reaper | Shares the host kernel (no gVisor/Kata). A kernel/runtime escape is out of scope. |
| Exfiltration of a provider key through the app | Opt-in allowlist only; keys go only to allowlisted hosts over TLS | If the user allowlists a host the repo controls (or an open relay), the key can leave. Allow only the provider's own hosts. |
| Proxy abuse (SSRF to metadata/LAN via an allowlisted name) | Resolved IPs must be global; port 443 only; CONNECT only | A name that legitimately resolves to a global IP is trusted. |
| Orphaned resources after a crash | Labels with owner pid and expiry; reaper at server start; `atexit` | `kill -9` of the server leaves containers until the next server start (or their TTL expiry check). |
| Repo `.env` baked into the image | Staging drops dotenv/key files | A secret committed under another filename is copied (and the analyser already flags literal credentials). |

## Known limits (what will still fail)
- Apps needing GPUs, local model weights downloads at runtime, a database/vector store service (Postgres, Redis, Chroma server), or other containers: no compose support, no internet at run time.
- Apps whose HTTP client ignores `HTTPS_PROXY` (Node `fetch` without a proxy agent, raw sockets) cannot reach an allowlisted provider; plain `http://` egress is never allowed; only port 443.
- Apps that write outside `/tmp` (read-only rootfs), need `exec` in `/tmp` (noexec), or run as root on a privileged port. Repo Dockerfiles that `COPY .env` fail the build.
- Streamlit/Gradio/CLI-only apps (no HTTP API, no `ask(question)` function): `no entrypoint detected`. Multiple required function arguments, methods, and apps whose entry is only `if __name__ == "__main__"` are not detected. Request bodies other than `{"question": ...}` need a `target_config` (request template and answer path).
- `requirements.txt` with `-r ../shared.txt`, private indexes or private git dependencies; dependencies installed at build need internet; unpinned extras (`uvicorn`, `fastapi`, `flask`) are installed at the latest version.
- Image size > 2 GiB, repo > 200 MiB staged, build > 10 min, startup > 90 s (raise `app_port` / fix the port if the health-wait times out).
- Docker Desktop on Windows/macOS: published loopback ports go through the VM; behaviour on Linux rootless setups and remote `DOCKER_HOST` is untested.
