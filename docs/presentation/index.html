A few successful prompts do not establish release confidence

Why prompts alone fail

  • Hallucination and unsupported claims
  • Grounding failures and bad citations
  • Prompt injection and tool misuse
  • Variability and model drift

What a release decision needs

  • Tests that adapt to the risk, not a fixed prompt list
  • Evidence you can audit later
  • Uncertainty, not a single score
  • A human who signs off

What we verify, and what we do not

Checked

  • Citation ids exist in the corpus
  • The expected source was cited
  • No invented numbers: each comes from the retrieved context or the question
  • The correct figure is stated

Not checked

  • Free-text unsupported claims
  • Semantic entailment (adapters exist, not wired in)
  • Bias and toxicity
A correct answer that quotes the user's wrong number is not a fabrication. Agreeing with the wrong number is caught by the expected-figure check.
Runs that error are missing evidence, never counted as failures5 / 12

Every failure is located, evidenced and turned into a test

Classify

  • Location: retrieval, guardrail, generation, memory… or unknown
  • The rule that fired and the evidence key
  • Access level shown: we cannot localise below it

Regress

  • Minimise the failing test
  • Admit only if it reproduces on the defect and passes on the clean app
  • Lineage kept back to the original failure

Evidence you can check, not just trust

Tamper-evident ledger

  • Hash-chained, append-only
  • Report regenerates byte-for-byte
  • Edit one stored event: detected

Who may write what

  • Models write drafts only
  • Evidence, verdicts and decisions: deterministic code
  • Sign-off: humans only
Known limit: the ledger is not signed. Someone with write access to the file could forge a consistent chain; an external anchor would be needed.
One command checks all of this against the ledgers: 23 of 23 checks passed on a simulated scenario9 / 12

Compare any models on the same generated suite

Suite and metrics

  • Grounded, false-premise, unanswerable, injection tests
  • Faithfulness · accuracy · abstention · injection resistance · consistency
  • Each model gets the same tests

Reading the result

  • Side-by-side intervals
  • A difference is claimed only if intervals do not overlap
  • Rate-limited calls = missing evidence
Honest label: it has run on simulated reference models. Real models are supported through OpenRouter but a full real-model benchmark is not yet validated.
